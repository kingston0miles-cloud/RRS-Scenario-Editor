# Редактор сценариев RRS

Визуальный редактор сценариев для [Russian Railway Simulator](https://github.com/maisvendoo/RRS):
расстановка поездов по карте маршрута, построение графиков движения (авторасчёт и ручные времена),
события сценария и экспорт готового сценария (`main.lua`, конфиги составов, расписания) без
программирования на Lua.

- **Язык и стек:** C++17, Qt 6 (Widgets), CMake 3.20+
- **Лицензия:** GPL-2.0 (как у RRS; редактор не заимствует исходники RRS, а читает те же файлы маршрута)
- **Платформы:** Windows (MinGW), Linux

## Возможности

- **Карта маршрута** — схема путей из `topology/` с масштабом колесом, поворотом, подсветкой
  траектории под курсором и правильных направлений пути по светофорам; клавиатура
  (стрелки, `+`/`-`, `F`, `R`).
- **Панель шагов** «1 · Маршрут → 2 · Составы → 3 · Расстановка → 4 · Графики → 5 · Проверка →
  6 · Экспорт» — прогресс работы и быстрый переход к нужному инструменту.
- **Расстановка поездов** — кликом по карте, перенос мышью с «призраком», разворот на месте,
  сцепки («локомотив + вагоны = новый поезд»), продолжения без локомотива.
- **Графики движения** — авторасчёт хода по физике и ограничениям скорости с запасами времени;
  тяговая оценка по данным конфигов единиц (конструкционные скорости вагонов ограничивают состав);
  **ручные времена** (правка в ячейках таблицы, якорь для последующего авторасчёта, экспорт
  «как введено»); **закрепления трассы** («через станцию X»); выбор пути каждой станции;
  платформы станций (`IsRightPlatform`/`IsLeftPlatform`); категории поездов для очерёдности пропуска.
- **Проверка графиков (F7)** — пересечения, встречное движение, заторы, отправление до старта;
  переход к проблеме на карте и кнопка «Добавить стоянку для пропуска».
- **События сценария** — триггеры и действия в визуальном редакторе; авто-события по графикам
  (маршруты приёма/отправления и светофоры) с флажком «не создавать».
- **Экспорт** — запись `main.lua` и расписаний с проверками; резервная копия `main.lua` и защита
  ручных правок; группы предупреждений «что не поедет»; сборка **«пакета-дополнения»** — готового
  дерева `routes/<маршрут>/scenarios` + `cfg/trains` для передачи другому игроку.
- **Проекты (.rrsproj)** — вся работа сохраняется в файл проекта; отмена/повтор действий (Ctrl+Z/Y);
  «Файл → Закрыть сценарий» (Ctrl+W) возвращает программу к стартовому состоянию без перезапуска.
- **Отчёты и подсказки** — счётчик замечаний с разбивкой, отчёт импорта с раскрываемым списком,
  пояснения «как поезд поведёт себя в игре», стартовый экран с выбором игры и маршрута.

## Сборка

### Windows (MinGW)

Нужны Qt 6 (компонент MinGW 64-bit) и CMake 3.20+. Из каталога проекта:

```bat
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_PREFIX_PATH=C:/Qt/6.x.x/mingw_64
cmake --build build
windeployqt build\rrs-scenario-editor.exe
build\rrs-scenario-editor.exe
```

### Linux

```bash
sudo apt install qt6-base-dev cmake g++
cmake -S . -B build
cmake --build build
./build/rrs-scenario-editor
```

Каталог маршрута можно передать аргументом командной строки: `rrs-scenario-editor routes/<имя>`.

## Использование

Кратко: **Файл → Открыть маршрут…** (каталог `routes/<имя маршрута>` из папки игры, внутри должна
быть папка `topology`) → выбрать состав в панели справа → кликнуть по пути на карте → задать график
кнопкой «График…» → **Проверка → Проверить графики сценария…** (F7) → **Файл → Экспорт сценария…**
(Ctrl+E).

Пошаговое руководство пользователя с описанием каждого окна и поля:
**[docs/user-guide.md](docs/user-guide.md)**.

## Тесты

```bash
cmake -S . -B build -DRRS_ROUTE_DIR=<путь к routes/experimental-polygon_v2.0>
cmake --build build
ctest --test-dir build --output-on-failure
```

13 наборов покрывают все уровни: чтение маршрута, каталог ПС, физику хода и графики, проверки
расписаний, экспорт/импорт, диалоги и главное окно. Без `RRS_ROUTE_DIR` проверки на реальном
маршруте «Испытательный полигон 2.0» пропускаются, остальные работают на синтетическом маршруте.
UI-тесты идут без дисплея (`QT_QPA_PLATFORM=offscreen`); каталог `RSE_SHOT_DIR` включает сохранение
снимков окон.

## Особенности данных RRS, учтённые в коде

- Длина траектории считается в 3D (с высотой), точки ближе 1 см склеиваются — как в симуляторе.
- Примыкания траекторий к стрелкам (`bwd*` — концом, `fwd*` — началом) и признак
  `fwdMinusTrajReversed` разобраны по всем 279 стрелкам полигона.
- Правильное направление пути выводится из поездных светофоров в `topology.xml` (литеры
  `SignalLiterFwd`/`SignalLiterBwd`, «Д»-литеры — выход на неправильный путь) и переносится по цепочке
  траекторий через стыки.
- Флаг `auto` включает автоведение, только если у крайней единицы состава есть модуль автопилота;
  такие составы помечаются «авто», редактор предупреждает, когда автоведение не включится, и даёт
  ссылку «Назначить модуль».
- Известные особенности данных полигона (битые ссылки, cp1251-комментарии в UTF-8 конфигах,
  `ModuleDir` = `vl60k`/`vl60pk` вместо собранного `modules/vl60`) показываются как предупреждения —
  подробнее в [docs/techdoc.md](docs/techdoc.md), §4.5.
